Project overview

People who use more than one AI assistant re-explain themselves every time they switch. Each vendor keeps its own memory and none of it travels. PersonaSync fixes that with a portable context layer: the user authors a persona and their personal context once, and PersonaSync delivers it into the tool they are using.

Phases 1 and 2 already exist and are live at app.personasync.dev: a persona web app with four context lanes and a scoring engine, and the Personal Context Layer (PCL), a set of MCP read tools that let other software read a user's context in a structured way. PersonaSync is the first consumer of the PCL.

This term project is Phase 3: a client that detects which AI tool is active, lets the user pick a persona, formats the context for that tool, inserts it, and logs what was shared with which tool. One rule runs through the whole product. The user writes and confirms everything the system knows about them, and anything an AI suggests is tagged and stays out until the user approves it.

The course work follows the Dennis, Wixom, and Tegarden object-oriented method: system request, requirements, use case and activity models, class and CRC models, sequence and state machine models, and a Software Requirements Specification with traceability. The SRS is the primary academic deliverable.
